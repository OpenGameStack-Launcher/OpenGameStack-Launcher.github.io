Specifications

System Requirements & Runtime

The OGS Launcher is engineered as a lightweight, native desktop application. It requires no installer, no background telemetry services, and no cloud account to operate.

Parameter Requirement Details
Operating System Windows 10 / Windows 11 (64-bit) Tested on modern x86_64 desktop installations
Application Runtime Godot 4.7.2 Custom desktop build with low idle memory footprint
Tool Cache Directory Shared immutable cache Content-addressed storage for downloaded tool archives
Network Connectivity Initial download only Completely offline operation after tool archives are cached
Distribution Model Portable zip archive Extract and launch immediately without administrative elevation
Workflows

Core Launcher Capabilities

Project Importing

Open any game project folder containing an ogs_stack.json manifest. The launcher automatically discovers required tools, verifies local cache integrity, and sets up one-click launch actions.

Isolated Tool Caching

Tool packages are cached in a shared, immutable directory. Multiple projects requesting the same tool version share binaries on disk, avoiding duplicate gigabytes of storage.

Offline Execution

Once tool archives are downloaded and verified, launch your entire game development pipeline completely offline. No telemetry pings, no cloud licenses, and no forced updates.

Seal for Delivery

Package your game source, configuration manifests, and exact tool binaries into an archived bundle. Create reproducible game archives ready for 20+ year long-term sustainment or team distribution.

Configuration

Manifest Architecture

Every Open Game Stack project relies on two canonical JSON files placed at the repository root. These files ensure your entire team launches the identical environment on any workstation.

Project Tool Stack: ogs_stack.json

The project tool manifest declares the exact frozen tools, versions, and categories required by the game. Version control this file with your source code so every collaborator uses the exact same binaries.

ogs_stack.json 
{
  "name": "MyGameProject",
  "version": "1.0.0",
  "tools": [
    {
      "id": "godot",
      "version": "4.7.2",
      "category": "Engine"
    },
    {
      "id": "blender",
      "version": "5.2",
      "category": "3D"
    },
    {
      "id": "krita",
      "version": "5.3.3",
      "category": "2D"
    }
  ]
}

Launcher Configuration: ogs_config.json

The launcher configuration controls project-specific runtime settings, relative launch paths, and tool flags. It coordinates how the launcher launches each tool and project file.

ogs_config.json 
{
  "project_name": "MyGameProject",
  "main_scene": "res://scenes/main.tscn",
  "engine_target": "godot@4.7.2",
  "cache_path": ".ogs-cache",
  "launch_options": {
    "editor_mode": true,
    "verbose_logs": false
  }
}
Reproducibility

The "Seal for Delivery" Workflow

When preparing a production milestone, team handoff, or long-term archive, use the launcher's Seal for Delivery action:

  • Audit Manifests: Confirm that all tools in ogs_stack.json and configuration values in ogs_config.json match current project requirements.
  • Lock Binaries: Bundle verified tool archives and engine runtimes alongside the project repository.
  • Generate Distribution Archive: Export a standalone, self-sufficient package that can be reopened decades into the future without relying on external servers or package managers.
